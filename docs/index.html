Smart Glass Canary

An ESP32 that listens for camera-equipped smart glasses — Meta Ray-Ban, Oakley Meta, Snap Spectacles and similar — and raises an alert when a likely pair comes into Bluetooth LE range. It signals on the onboard LED, on an optional buzzer, and over MQTT.

This page flashes the firmware onto a board over USB and then sets up Wi-Fi, with no toolchain to install and no files to edit.

Before you start: this needs Chrome or Edge on a desktop computer.

Flashing uses WebSerial, which only those browsers implement. Firefox and Safari cannot do it, and neither can any browser on a phone or tablet — including Chrome on Android and iOS. If you are reading this on a phone, come back on a computer.

Install

  1. Plug the ESP32 into your computer with a USB data cable. Charge-only cables power the board but carry no data, and the board looks identical either way — this cost us an afternoon during development. If no port appears in the browser dialog, suspect the cable first.
  2. Click Install below and pick the serial port for the board.
  3. When flashing finishes, the same page asks for your Wi-Fi name and password.
This browser cannot flash the device. Open this page in Chrome or Edge on a desktop computer. Flashing needs an HTTPS connection. Open this page over HTTPS.

Wi-Fi credentials travel down the same USB serial link, using Improv Wi-Fi. There is deliberately no setup access point to join: the device stores the settings in NVS, connects, and reports its own address back. The firmware image itself contains no credentials, so the same file can be handed to anyone.

What it cannot do

Read this part. The failure mode here is a silent false negative, and a canary that says nothing while glasses are present looks identical to one working perfectly.

Meta glasses stop advertising entirely once they are connected to their owner's phone. At that point they are invisible to every Bluetooth LE scanner, not just this one. So the canary reliably catches glasses powering on and pairing, and goes blind during an actual recording session. That is device behaviour, not a bug in this firmware, and no amount of signature tuning fixes it.

Treat a detection as good evidence. Treat silence as weak evidence — it is not proof that nobody nearby is recording.

Recording indicators on these products are separate from the radio, so a detection tells you glasses are present, never whether a camera is running. This is an awareness tool, not a guarantee.

Detection also degrades or fails when:

  • The product is not Bluetooth LE detectable at all. Xreal Air and One are driven over USB HID and expose no Bluetooth path.
  • A firmware update changes an advertised name. Detection depends on a signature table, so an unknown or updated product can go unseen.
  • You rely on range. RSSI swings with orientation, bodies and walls; the default -75 threshold is a rough proxy for "same room", not a measurement.

After setup

MQTT is optional. With it enabled the device publishes events to canary/glasses/event and keeps a retained present/clear value on canary/glasses/state. Without it the device works standalone: the LED and the buzzer alert on their own, and Wi-Fi is only needed for timestamps and push outputs.

To clear stored Wi-Fi credentials later and return the device to setup, hold the BOOT button while powering on and keep holding for about three seconds. It keeps detecting glasses the whole time — only the network side goes idle.
